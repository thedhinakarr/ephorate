With coding agents, firms opened 36% more pull requests. Review took 56% longer. Resolved issues rose about 14%.

Writing got fast. Reading did not, and there is now more to read for each piece of finished work. Two habits of coding agents make it worse.

Larger patches to inspect

In a comparison of 28 automated repair approaches, each produced larger patches on average over its resolved SWE-bench Verified tasks than the corresponding developer patches. Size alone does not show which lines are unnecessary.

How the check works

One question, asked of every piece of the change: which test fails if this is removed?

  1. Split the change

    Modified source files use diff-hunk units. New and deleted files use whole-file reversions, including file existence. Changed test files are left whole. They are the judges.

  2. Check the baseline

    Your test command runs twice on the full change. Both runs must pass consistently. Failure, changed outcomes or changed test collection stops the check; flaky tests are not ignored.

  3. Remove a unit, run the tests

    Bounded trials use independent temporary clones. An individual unit’s assertion witness must reproduce on removal, with a fresh passing head control. A combined diagnostic trial records a separate group observation.

  4. Give each unit a verdict

    Recorded evidence determines the individual verdict. Group observations never promote member verdicts. Unstable, inconclusive or group-only results stay unjudged.

  5. Report

    A summary in the terminal, a JSON file for agents and CI, and later one comment on the pull request.

Four verdicts

Each unit gets exactly one. When Ephorate cannot tell, it says so.

VerdictWhat the trial showedWhat to do with it
heldAn individual unit’s explicit assertion witness repeats on removal, with a fresh passing head control.Read the witness. It establishes neither correctness nor dependence on every line in the unit.
looseA valid removal trial passes without a witness.Investigate whether the code is needed and whether the tests should detect its removal.
inertThe configured comparison finds the same syntax tree with or without the unit.Consider source-text consumers and directives. AST equality is not behavior proof.
unjudgedUnsupported file, unstable evidence, structural failure, timeout or exhausted budget.Read it; no conclusion was established.

Built on known techniques

Ephorate is not the only tool in this area, and the trial at its centre is decades old. Here is how it sits next to what you may already run.

Kind of toolWhat it doesWhat Ephorate does instead
Mutation testingMakes small edits to code and scores how many your tests notice.Removes whole pieces of one change and returns a reading list, not a score.
Patch minimizersDelete the parts of a change that tests do not need.Runs the same trial and stops at the report. Untested code that matters looks the same as code that does not.

What a verdict does not tell you

The check is narrow on purpose. These are its edges.

Held is not correct

It records an individually confirmed unit witness. Group observations cannot promote member verdicts. Whether an assertion checks the right requirement is still a person’s call.

It needs tests that run in minutes

Every unit costs at least part of a test run. A slow or failing suite rules the check out.

Some changes cannot be judged

Configuration, migrations, infrastructure and most interface work come back unjudged.

A shallow test can hold a line

An agent can write a weak test to clear a verdict. The tests still need reading.

Four rules in the design

They keep the tool small enough to audit.

No language model inside

Verdicts follow recorded evidence. Test execution can still be unstable; repeated witnesses and head controls do not eliminate every source of flakiness.

Your checkout is preserved

Trials use independent temporary clones. These are not sandboxes: test commands and plugins must be trusted and can affect resources outside the clone.

Tests are the judges

Test files are never removed or changed, and a change that edits existing tests is flagged.

A local engine

The CLI itself makes no network calls or uploads. That does not constrain test subprocesses. The later GitHub Action will explicitly publish its documented comment and report artifacts.

Questions

Does Ephorate replace code review?

No. It tells a reviewer where to start and gives a coding agent something to fix first. Someone still decides whether the tests ask for the right thing.

Will it delete code?

No. It reports. Where tests are thin, code that matters and code that does not look the same to it, so the decision stays with a person or with the agent that wrote the change.

Is this mutation testing?

It is a close relative. Ephorate reverts individual units from one change and reports confirmed assertion witnesses, undetected removals and uncertainty. A combined diagnostic trial records only a separate group observation.

How long does a check take?

Not measured yet. The first version runs the full suite for every unit. Later versions run only the tests that reach the unit.

Which languages?

Python with pytest first. TypeScript is planned after that.

Where does the name come from?

The ephorate was Sparta’s board of five elected overseers, who could call even the kings to account. It is pronounced EFF-er-it.

The first real numbers will come from merged agent pull requests.

Before anything is polished, the engine gets replayed on real changes and the verdicts are audited by hand. The method and the results will be in the repository, whichever way they come out.
