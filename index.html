After AI agent adoption, time from pull request submission to merge rose an estimated 56.1% in one study.

Review capacity depends on who knows the code and where their time is already going. Ephorate’s plan is to test those constraints against a team’s own history before forecasting what more pull requests would do.

Chen and Stratton, “Artificial Intelligence in the Firm: Bottlenecks in Software Production” (Harvard University, 2026), a study of 655 firms. This is a study estimate, not a forecast for your team or evidence that Ephorate works.

How it is planned to work

Read GitHub history, map the shared review capacity, and test the model against the past. Scenarios come after that credibility check.

  1. Read the history

    Use a read-only token to collect pull request metadata, review events and changed paths, plus CODEOWNERS configuration where present. Detectable coding agents and dependency bots are counted separately.

  2. Map areas and reviewers

    Measure arrivals, prior familiarity and the distribution of reviewing across areas. Account for people who review in more than one area.

  3. Measure the queue

    Separate time waiting for a human response from elapsed time after that response, and report formal human review coverage alongside both.

  4. Test against the past

    Fit on earlier history and predict a later period. Compare waiting-time predictions with a simple baseline and report errors before treating scenarios as useful forecasts.

  5. Test a change

    If the backtest supports it, simulate more agent pull requests or a different review arrangement. Show assumptions, backtest error, queue effects and coverage together.

Understand the system. Don’t grade the people.

Four rules shape the design.

Read-only GitHub access

The tool will collect history and suggest changes. It will never merge, approve, post reviews, change labels or edit repository settings.

Area-level views first

Reports will describe the distribution of work. Optional names will support reviewer planning, with one option to hide per-person detail. No individual rankings or performance grades.

Metadata, not source code

The collector will retain identifiers, timestamps, paths and counts. CODEOWNERS is the only repository configuration it will fetch; source code will not be stored or sent elsewhere. No language model is required.

Errors beside forecasts

The plan requires time-ordered backtests, a simple comparison baseline and disclosed assumptions. Unsupported scenarios must say so, and shorter waits must be shown alongside review coverage.

Questions

Can I run it today?

No. The review capacity tool is planned, and no validated forecast is available. Follow the repository for the implementation and backtest results.

What access is planned?

A read-only GitHub token for pull request and review metadata, changed paths and CODEOWNERS configuration. The tool will write only its own metadata store and report files where you run it.

Will it change our reviews or CODEOWNERS?

No. It will only suggest changes for a person to consider. It will not modify reviews, ownership rules, labels or repository settings.

Can it tell us who is slow?

That is not its purpose. GitHub records elapsed workflow time, not a person’s review effort. The default reports will be about areas and queues, with no individual rankings. Seniority will never be inferred as fact.

Will it identify every agent-written change?

No. Known bot accounts and recognised co-author trailers can identify some agent use. Reports will state that detectable agent authorship undercounts actual use and will separate dependency bots.

What if the forecast does not hold?

The backtest is a gate. If the model cannot beat the simple baseline, the report must say so and scenario development stops for owner review. Any later forecast must show its backtest error and assumptions.

Test the forecast against the past first.

The first question is whether review capacity can be forecast well enough to guide a change. Ephorate’s plan puts that test before scenarios or claims of saved time.
