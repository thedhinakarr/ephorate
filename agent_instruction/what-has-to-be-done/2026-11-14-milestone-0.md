## 5. Edge cases and failure modes

- Missing Docker daemon, denied socket access, unavailable image/architecture, or a port conflict: fail clearly; do not claim the health criterion passed or bind to a public interface as a workaround.
- Missing local passwords: Compose fails before startup with variable names only. Use `docker compose config --quiet` when validating; unredacted configuration output can expose interpolated credentials.
- Dependency or interpreter download failure: report the failing stage; do not remove pins, weaken strict checking, or pretend the installed host Python matches the project pin.
- Temporal volume permissions or startup timeout: inspect the development-only service, preserve state, and fix the concrete problem. Do not use `down -v` or delete volumes.
- Existing source files or concurrent work: inspect before replacing anything and preserve unrelated changes.
- Health is liveness, not infrastructure readiness. A passing route test alone cannot substitute for Compose smoke testing.
- `make backtest` returns failure until the real M3 pipeline exists, even if a `REPO` argument is provided.
- No remote means hosted Actions cannot be observed yet. Distinguish a valid workflow plus passing equivalent local commands from an actual hosted CI run.
