How it works

Ephorate sits on top of the AI reviewer and CI you already use. It adds one thing they lack: a risk number checked against what happened afterwards.

  1. Learn from your history

    It reads your past changes and traces each incident, revert and hotfix back to the change that caused it.

  2. Score each pull request

    Size, the files touched, who knows them and how those files have behaved before become a probability, calibrated so that 1% means 1%.

  3. Apply your policy

    A short file in your repository sets the threshold and names the paths that always need a person.

  4. Route the decision

    Changes under the threshold merge once tests and review checks pass. The others go to the reviewer most familiar with the code.

  5. Track what happens

    Every merge is followed. When something breaks, the link feeds the next model refresh and shows up in your escape rate.

One check on the pull request, one file in the repo

Engineers see a number, a comparison and a decision. Leads set the rules in a file that is versioned and reviewed like any other code.

The policy

# .ephorate/policy.yml
threshold: 0.005          # 0.5% incident risk

always_review:
  - "services/payments/**"
  - "infra/terraform/**"
  - "**/migrations/**"

required_checks:
  - ci/tests
  - ai-review

mode: shadow              # report, don't enforce

A missing or invalid policy sends every change to a reviewer.

Built to be trusted with the merge button

Four rules shape the design.

Read-only by default

Ephorate reads history and incidents and writes one check. It does not merge, approve or push unless you switch that on.

Shadow mode first

It starts by reporting what it would decide. You compare that with what happened before letting it gate anything.

The language model never decides

A language model may describe a diff as one input. The decision comes from a calibrated statistical model and your policy file.

Your code is not kept

Source is processed in memory to extract signals. What is stored is the signals, file paths and commit identifiers.

Questions

Does Ephorate replace our AI code reviewer?

No. It doesn’t comment on code. It uses your reviewer’s result as one required check and decides whether a person also needs to look.

Will it merge code without asking?

Not unless you turn that on. It starts in shadow mode, where it only reports the decision it would make.

What access does it need?

Read access to your Git history and pull requests, and to incident records from tools such as PagerDuty or Datadog. It writes a check and nothing else.

We don’t have many incidents. Does it still work?

Reverts, hotfixes and bug-fix commits count as outcomes too, so most active repositories have enough to learn from. With less history the estimates are wider, and the report says so.

Who is it for?

Engineering teams where coding agents have filled the review queue faster than senior engineers can clear it.

Where does the name come from?

The ephorate was Sparta’s board of five elected overseers, who could hold even the kings to account. It is pronounced EFF-er-it.
